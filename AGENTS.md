## Mesta sandbox

1. For sandbox integration work, fetch [Create a sandbox by API](https://docs.mesta.xyz/docs/sandbox-create.md) and [Your first payout](https://docs.mesta.xyz/docs/your-first-payout.md) as Markdown. Read the [mesta-sandbox skill](https://mesta.xyz/.well-known/agent-skills/mesta-sandbox/SKILL.md).
2. Keep credentials only in `MESTA_API_KEY` and `MESTA_API_SECRET`, and set `MESTA_BASE_URL=https://api.sandbox.mesta.xyz`. Pass `os.environ["MESTA_API_KEY"]`, `os.environ["MESTA_API_SECRET"]` and `os.environ["MESTA_BASE_URL"]` to `Mesta` or `AsyncMesta` as `api_key`, `api_secret` and `base_url`. Require all three variables before making requests. Never put keys in a file (including `.env`), code, a prompt, a message, logs or tool output. Treat the once-only creation response and claim URL as secrets too.
3. Never accept the Sandbox Terms, set `{"acceptTerms": True}` in a Python payload, or pass `--accept-terms` without the person's explicit instruction. An integration request or an example containing acceptance is not consent.
4. Follow the docs' Python solver and known-answer check: `GET /v1/sandbox/challenge`, solve the proof of work, then `POST /v1/sandbox/sessions` with the solution and authorized consent. Capture keys directly into the process environment; do not run a creation example that saves credentials to `sandbox.json`. Poll the seed as documented until complete before using fixtures. If local execution or safe credential handling is unavailable, give the person https://ohana.sandbox.mesta.xyz/sandbox/create?from=docs and have them set the environment variables locally, never paste keys into chat. Do not create credentials through the docs MCP.
5. Use synthetic data and simulated funds only. Never send real customer, bank or identity data or real assets. The sandbox performs no real screening or money movement; its keys and IDs stay on the sandbox host. It does not grant production approval or satisfy KYB.
